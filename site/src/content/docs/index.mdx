Your coding agent does the design work, and benchhand holds the process around it.
The design record keeps a project's requirements, parts, decisions and approvals as files in your repository, and the contracts define every shape in it.
The planned MCP server tells the agent which stage the design is at and what to do next, asks you to approve each stage, and runs the checks through providers.
These pages describe the whole system. Parts that are planned carry a Planned label.

## The workflow

<div class="bh-split">
<section class="bh-available" aria-labelledby="the-record-and-its-contracts">

### The record and its contracts

- **One source of shapes.** The record, job, finding and provider-protocol shapes are defined once in `contracts/`. The JSON Schemas, Python models and TypeScript types are generated from them. [Read the contracts](/reference/contracts/).
- **A record you can audit.** `benchhand-core` reads, validates and writes a project's `hw/` record against those contracts. It reports every problem it finds in a record, not only the first.
- **Two commands.** `benchhand version` prints the version. `benchhand record migrate HW` converts a record from `record_version` 2 to version 3. It is a dry run until you add `--apply`, and an apply backs up the files it changes first.

The MCP server, the flow engine and the providers are planned, and the next panel describes them.

</section>
<section class="bh-planned" aria-labelledby="the-guided-design-flow">

### The guided design flow

<PlannedAside phases={[2, 3, 4]} />

- **One interface.** You run the workflow through MCP. The `benchhand` command is a thin launcher and admin tool.
- **Guidance from the server.** The agent calls `flow.guide`, and the server answers with the current stage, its tools and the next action.
- **Gates guide, they don't guard.** Each gate asks for your approval by default. A project can set a gate to `chat` or `auto` in `hw/policy.yaml`, and the record keeps every relaxation.
- **Scoped approvals.** An approval names the items it covers. A later change to one of them reopens only that item.
- **Providers for everything.** Kernels, FreeCAD, solvers, renderers, process checks and storage plug in behind one provider protocol.

Most manual and tutorial pages describe this flow. [The list of planned pages](/planned/) shows which ones are outlines.

</section>

## Who it is for

- Engineers and makers who design parts with an AI coding agent and need a record they can audit.
- Teams who write providers or policies for their own processes.
- Contributors to benchhand: start with [the architecture](/architecture/) and [the decision records](/adr/).
