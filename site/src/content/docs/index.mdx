## What works today

- **The contracts.** The record, job, finding and provider-protocol shapes are defined once in `contracts/`. The repository generates the JSON Schemas, Python models and TypeScript types from them. [Read the contracts](/reference/contracts/).
- **The record library.** `benchhand-core` reads, validates and writes a project's `hw/` record against those contracts. It reports every problem it finds in a record, not only the first.
- **Two commands.** `benchhand version` prints the version. `benchhand record migrate HW` converts a prototype record (`record_version` 2) to version 3. It is a dry run until you add `--apply`, and an apply backs up the files it changes first.

Nothing else runs yet: there is no MCP server, no flow engine and no provider to start.

</section>

## The planned workflow

<PlannedAside phases={[2, 3, 4]} />

- **One interface.** You run the workflow through MCP. The `benchhand` command is a thin launcher and admin tool.
- **Guidance from the server.** The agent calls `flow.guide`, and the server answers with the current stage, its tools and the next action.
- **Gates guide, they don't guard.** Each gate asks for your approval by default. A project can set a gate to `chat` or `auto` in `hw/policy.yaml`, and the record keeps every relaxation.
- **Providers for everything.** Kernels, FreeCAD, solvers, renderers, process checks and storage plug in behind one provider protocol.

Most manual and tutorial pages describe this workflow. [The list of outlines](/planned/) shows which pages are outlines, and the phase that writes each.

## Who it is for

- Engineers and makers who design parts with an AI coding agent and need a record they can audit.
- Teams who write providers or policies for their own processes.
