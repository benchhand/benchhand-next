## Legend

Each table is a type: a contract root, a named `$defs` object or union, or an object written inline. An inline object `b` of property `a` is named `a.b`. Each row is a field, and `req` marks a required one. A box with a dashed border groups the types that one root owns.

- Colours: blue is a contract root, teal is any other type, purple is a union (`«union»`, or `«abstract»` when every branch fixes one property with a `const`). A grey dashed box is a stub: a type that another diagram of the same contract or another contract owns. It has no fields.
- **Enums have no colour.** D2 cannot colour one table cell, and the model has no node for an enum. An enum shows in the type of its field: its values when there are six or fewer, and its name when it is a named definition. Each contract page lists its enums in one table.
- Arrows: a solid line is composition, a type nested in another (inline, or a `$ref` within the contract). A dashed line is association, a `$ref` to a type of another contract. A hollow triangle is inheritance: a branch of a union, or a type that extends another with `allOf`. A label lists the fields and the number held: `1..*` is at least one, `0..*` any number, `2` exactly two, `0..1` an optional, nullable or alternative one.
- In a type, `T[]` is an array of any length, `T[1..*]` at least one, `T[2]` exactly two. `[A, B]` is a tuple. `T by key` is an object whose every value is a T, and a `[key]` row holds the other keys of an object that also has named properties. Values are JSON: `null`, `true`, and a string bare.
- In the overview, blue is a record document, amber is a library (shared definitions and no document of its own), and an arrow counts the `$ref`s from one record contract to another.
- A diagram is also a link target: in the `.svg` file, a stub and an overview node link to the diagram that owns the type. In a Markdown page the image is static, so the contract pages list the related contracts.
