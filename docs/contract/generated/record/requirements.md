# benchhand requirements record (hw/requirements.yaml)

Generated by tools/gen (`just contracts`). Do not edit. Source: [`contracts/record/requirements.tsp`](../../../../contracts/record/requirements.tsp).

- `$id`: `https://benchhand.github.io/benchhand/contracts/record/requirements.schema.json`
- Version: `1.0.0`

Requirements, preferences, assumptions and open questions, kept apart: a mandatory requirement is never downgraded into a preference or an assumption to pass, and an unknown with a filled-in reason is still unknown. Record version 2 carries all four lists; preferences, assumptions and open_questions may be empty.

## Root

Type: object

| Property | Type | Required | Description |
|---|---|---|---|
| `preferences` | array of object | no | What ranks feasible options; a preference never compensates a mandatory failure |
| `assumptions` | array of object | no | Bounded statements taken as true for now, each with its owner and the obligation that would validate it |
| `open_questions` | array of object | no | Questions still to answer; material_to_choice or safety_relevant open questions block a final material/process recommendation |
| `requirements` | array of object | yes | `minItems: 1` |

No other properties are allowed.
